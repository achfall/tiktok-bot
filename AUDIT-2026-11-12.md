**Audit tiktok-bot — 12 November 2026**

Audit dilakukan terhadap working tree saat ini, termasuk perubahan Schedule dan
pengelolaan slot Chrome yang sudah ada. Perubahan lama dipertahankan. Temuan
di bawah diperbaiki dan diuji dengan data sementara; tidak ada upload, publish,
atau Schedule baru yang dikirim ke TikTok sebagai pengujian.

**Cakupan pemeriksaan**

Alur produksi panel/HTTP/CLI, validasi pengaturan, supervisor dan child process,
kuota harian dan batch lintas tengah malam, klaim dan rekonsiliasi, arsip,
pemilihan produk, rotasi musik, recovery sleep, launcher macOS/Linux, koneksi
CDP, caption provider, tampilan form, serta kondisi lokal database dan resource.
Script mapping dibaca sebagai alat diagnostik manual; tidak dijalankan untuk
mengunggah atau mengubah konten akun asli.

**Temuan dan perbaikan**

| Area | Masalah yang ditemukan | Perbaikan |
|---|---|---|
| Kepemilikan Chrome | Browser yang telah dibuka manual ikut ditutup setelah task sukses atau saat recovery. | `prepare_browser` mengembalikan kepemilikan. Bot hanya menutup browser yang dibuka prosesnya; Chrome manual dipertahankan, termasuk mode Schedule. |
| Penumpukan resource | Kegagalan sebelum submit mempertahankan Chrome milik bot walau klaim sudah dilepas. | Setelah diagnostik, Chrome milik bot dibersihkan pada kegagalan sebelum submit. Browser dengan hasil uncertain tetap dipertahankan. |
| Slot Chrome | Metadata lama/Chrome background sebelumnya menghalangi pekerjaan berikutnya. | Kuota berdasarkan flock aktif, bukan keberadaan proses Chrome. Pelepasan, crash, concurrency, dan penurunan batas diuji. |
| Protokol CDP | Error protokol diabaikan; `Input.enable` dipanggil padahal tidak tersedia. | Error CDP/JavaScript menghentikan langkah. `Input.enable` dihapus. Ketidaktersediaannya dikonfirmasi lewat `/json/protocol` Chrome yang hidup. |
| Koneksi macet | Event terus masuk bisa membuat penantian balasan CDP tidak selesai; beberapa close-tab tanpa timeout. | Deadline CDP 30 detik, timeout close-tab 3 detik, validasi endpoint lokal/port akun. |
| Socket/tab | Koneksi WebSocket tidak selalu ditutup pada interupsi; tab baru dapat tertinggal bila koneksi gagal. | Cleanup di `finally`, termasuk hanya menutup tab baru milik percobaan ketika koneksi gagal. |
| Clipboard | Bot meminta permission clipboard untuk TikTok padahal alur saat ini memakai Input.insertText. | Permintaan permission yang tidak diperlukan dihapus. Tes alur produksi memeriksa tidak ada grant clipboard. |
| Status job | Orchestrator berhenti karena error tetapi exit 0; panel menampilkan Proses selesai. | Hasil gagal diteruskan menjadi exit code 1 dan status Gagal. Worker nyata dengan file fixture tidak valid menguji jalur ini. |
| Supervisor | Kegagalan supervisor dapat meninggalkan child yang masih bekerja; jalur exception tidak menunggu penghentian. | SIGINT + wait, lalu kill bila timeout; watchdog child menghentikan dirinya bila parent hilang. Tidak ada reset otomatis klaim. |
| Recovery sleep | Persiapan dapat diulang tanpa batas jika berulang kali terputus. | Maksimal dua recovery sebelum submit. Setelah submit dimulai, hasil ambigu tetap tidak diulang otomatis. |
| Penulisan konfigurasi | Mode bisa berubah sebelum pengaturan gagal disimpan; panel dan CLI bisa saling menimpa read-modify-write. | File lock lintas proses, simpan konfigurasi sebelum perubahan mode, dan rollback konfigurasi bila CLI gagal. |
| Validasi pengaturan | NaN/Infinity bisa menyebabkan error internal; endpoint settings dapat mengubah akun yang sedang berjalan. | Angka tidak terbatas ditolak; akun aktif/tertahan memakai pemeriksaan idle yang sama. |
| Scheduler panel | Error SQLite yang tidak tertangani dapat mematikan thread scheduler. | Exception satu tick dicatat tanpa payload rahasia; tick berikutnya tetap dijalankan. |
| Caption | Client Gemini tidak dibatasi timeout/ditutup secara eksplisit; pesan exception dapat memuat secret. Caption duplikat tetap dipakai. | Timeout request 60 detik, client ditutup, error log hanya nama kelas, caption duplikat menghentikan proses sebelum upload. |
| Helper finalisasi | Helper submit tidak memasukkan batas harian ke transaksi submit. | Memakai `max_per_day` dari registry yang sama ketika `begin_submission`. |
| Script upload lama | Pipeline lama melewati aturan klaim/kuota modern pada akun pribadi. | Entry point `full_test_post.py` dan `test_save_draft.py` dinonaktifkan untuk seluruh akun. Kode dipertahankan sebagai referensi. |
| Launcher | launchd membuka Chrome sebelum pemeriksaan antrean/jam/slot; launcher cron/tmux usang masih dapat dieksekusi. | launchd langsung mendelegasikan ke orchestrator, dengan guard aktivasi tetap ada. `boot_start_all.sh` dinonaktifkan. Tidak ada launchd/cron diaktifkan. |
| File dan disk | File kosong/sangat besar dari folder lokal bisa diteruskan ke Chrome; upload panel tidak memeriksa ruang tersisa. | Validasi bersama MP4/MOV 1 byte–2 GB, tolak symlink, cadangan disk 256 MB sebelum upload panel. Tidak mengklaim validasi codec. |
| CLI dan produk lama | Akun nonaktif bisa dijalankan langsung melalui CLI; NULL product_id pada log lama dapat membuat `NOT IN` menyembunyikan semua produk. | Akun nonaktif/mode tidak dikenal ditolak; NULL dikecualikan dari subquery produk. |
| Riwayat Schedule | ATTACH URI read-only gagal pada koneksi SQLite biasa tanpa `uri=True`; pembacaan seluruh metadata tumbuh tanpa batas. | Koneksi read-only terpisah, verifikasi account/content, dan pembacaan dibatasi pada ID riwayat yang ditampilkan. |
| Konsistensi Schedule | Commit ke dua file tidak crash-atomic bila journal WAL digunakan. | Schedule menolak mode journal yang tidak mendukung rollback journal; tidak mengubah mode database produksi otomatis. |
| Pengaturan batch selesai | Memulai ulang batch yang sudah selesai pada hari sama tetap memakai jam/jeda lama. | Batch selesai membaca pengaturan baru; kuota dan slot terpakai tidak direset. Batch yang benar-benar terputus tetap melanjutkan konfigurasi semula. |
| Izin secret | `.env` memiliki mode 0644. | Diubah menjadi 0600, tanpa mengubah isi. Nilai key yang saat ini terpasang tidak ditemukan dalam 59 file log yang diperiksa. |

Pembatasan transaksi lintas file mengikuti
[dokumentasi SQLite ATTACH](https://www.sqlite.org/lang_attach.html): jaminan
atomic lintas database memerlukan main database berbasis file dan journal yang
bukan WAL. Keempat database lokal saat pemeriksaan memakai DELETE.

**Bukti verifikasi**

- Seluruh suite: **165 tes lolos** melalui `venv/bin/python -m unittest discover -s tests -v`.
- Fault tests tambahan di `tests/test_audit_faults.py`: error protokol, event
  flood, endpoint salah, koneksi putus, interupsi, stop paksa, kehilangan parent,
  config disk failure/rollback/concurrency, journal WAL, file tidak valid,
  status worker nyata, launcher inert dan browser manual.
- Tes slot memakai beberapa proses nyata dan memeriksa maksimum dua pemegang
  slot, pelepasan setelah crash, serta metadata lama yang tidak menghalangi.
- Panel diuji di browser dengan akun fixture terpisah: tiga mode, tampilan
  pemisah, simpan dan buka ulang pengaturan. Tidak menjalankan automasi.
- `pip check`: tidak ada dependensi terpasang yang rusak. Ini bukan pemeriksaan
  seluruh CVE dan bukan bukti bahwa semua versi merupakan versi terbaru.
- Pemeriksaan syntax Python, shell launcher, dan `git diff --check`.
- `PRAGMA quick_check` menghasilkan `ok` pada `tiktok_bot.db`,
  `schedule_posts.db`, `music_rotation.db`, dan `control_panel.db`.
- Tidak ada referensi submission_log_id yatim, video tertahan, atau job aktif
  pada snapshot pemeriksaan. Tidak ada status antrean produksi yang direset.

**Kondisi Mac yang teramati**

RAM 8 GB, swap terpakai sekitar 917 MB, ruang disk kosong sekitar 27,5 GiB,
Chrome 150.0.7871.125. Terdapat 74 proses terkait Chrome, termasuk helper,
renderer, dan crashpad; angka ini bukan jumlah jendela atau jumlah bot.
Tidak ditemukan laporan Chrome pada folder `~/Library/Logs/DiagnosticReports`
yang diperiksa. Snapshot ini tidak membuktikan penyebab crash tertentu.

Batas dua berlaku untuk sesi bot aktif. Browser manual dan browser hasil
uncertain yang sengaja dipertahankan tetap dapat memakai RAM di luar batas itu.
Bot tidak menutup browser kerja pengguna dan tidak mengubah batas menjadi satu,
menonaktifkan GPU, atau menghapus profil/cache tanpa dasar pengujian.

**Batas audit dan risiko yang masih perlu diperhatikan**

Pembaruan Quit: `browser_process.py` menambahkan verifikasi PID aplikasi benar-benar
keluar, dengan fallback SIGTERM terarah setelah Browser.close. Satu Chrome nyata
dengan profil sementara sudah diuji tanpa TikTok: startup sekitar 2,47 detik,
Quit sekitar 0,79 detik, PID aplikasi hilang dan CDP tidak lagi merespons.
Angka satu percobaan ini bukan benchmark untuk seluruh akun. Suite setelah
pembaruan Quit: 173 tes lolos. Tes tambahan di
`test_browser_quit.py` memeriksa PID reuse, PID tidak valid, state unknown,
perubahan endpoint, dan pemilihan PID browser alih-alih renderer.

- Belum ada pengujian upload/submit nyata setelah perubahan audit. Perubahan
  UI TikTok, login/challenge, codec rusak, jaringan, GPU/driver dan kehabisan RAM
  tetap dapat menggagalkan task; kegagalan ini tidak dijanjikan hilang seluruhnya.
- Tidak dilakukan stress test yang sengaja membuat Chrome pengguna crash.
  Batas ukuran file bukan verifikasi codec/durasi seluruh koleksi video.
- Setelah SIGKILL, reboot atau putus daya, job/claim dapat memerlukan pemeriksaan
  operator. Watchdog tidak menggantikan rekonsiliasi hasil TikTok yang belum pasti.
- JSON konfigurasi dan SQLite mode akun bukan satu transaksi lintas media.
  Rollback kegagalan sinkron diuji; putus daya tepat di tengah penyimpanan masih
  memerlukan pemeriksaan pengaturan sebelum menjalankan bot kembali.
- Arsip melibatkan filesystem dan SQLite. Interupsi keras di antara keduanya
  dapat membutuhkan pemulihan arsip manual. Status used tetap dipertahankan agar
  video tidak otomatis diposting ulang. Skenario putus daya fisik tidak diuji.
- Script mapping/resume diagnostik manual tidak semuanya diubah menjadi alat
  multi-akun. Gunakan panel/orchestrator untuk pekerjaan rutin; jangan gunakan
  script mapping sebagai pengganti pipeline produksi.
- Audit ini tidak membuat jaminan bebas bug, tidak melakukan penetration test
  hosting publik, dan tidak mengaktifkan layanan/posting untuk pengujian.
